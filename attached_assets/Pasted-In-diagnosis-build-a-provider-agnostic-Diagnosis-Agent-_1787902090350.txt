In /diagnosis/, build a provider-agnostic Diagnosis Agent. Structure it like this:

1. Create /diagnosis/base_provider.py defining an abstract base class LLMProvider with

   one method: generate_diagnosis(prompt: str) -> str (returns raw text response).

2. Create /diagnosis/gemini_provider.py implementing GeminiProvider(LLMProvider) using

   the google-generativeai SDK, reading GEMINI_API_KEY from env, model

   'gemini-1.5-flash' (fast + free-tier friendly). Wrap the call in try/except and raise

   a custom ProviderError on any failure (auth, rate limit, timeout) so the caller can

   catch it distinctly from a JSON-parsing error.

3. Create /diagnosis/groq_provider.py implementing GroqProvider(LLMProvider) using the

   groq SDK (or OpenAI-compatible client pointed at https://api.groq.com/openai/v1),

   reading GROQ_API_KEY from env, model 'llama-3.3-70b-versatile'. Same ProviderError

   wrapping.

4. Create /diagnosis/diagnosis_agent.py with:

   - build_prompt(risk_event_row) -> str: includes risk_category, amount_at_risk,

     failure_code (if any), days since event, customer's contact_count_last_7d, and

     whether they're a repeat offender (query prior risk_events for this customer_id).

     Instruct the model to respond ONLY with valid JSON, no markdown, no preamble, in

     exactly this shape:

     {

       "root_cause": "<one sentence explanation>",

       "recommended_action": "<one of: send_reminder, retry_payment, offer_discount,

          send_payment_link, switch_payment_method, escalate_to_human>",

       "recommended_channel": "<one of: email, sms, whatsapp>",

       "recommended_discount_pct": <number 0-100>,

       "confidence": <number 0-1>

     }

   - get_provider_chain() -> list[LLMProvider]: reads env var LLM_PROVIDER

     ('gemini' or 'groq', default 'groq'). Returns a list with the requested provider

     FIRST and the other provider as a fallback SECOND, so both are always available

     as a chain regardless of which is primary.

   - diagnose_risk_event(risk_event_row): builds the prompt, then tries each provider

     in get_provider_chain() in order. For each attempt: call generate_diagnosis(),

     parse the JSON defensively (strip markdown fences, try/except). If the provider

     raises ProviderError OR JSON parsing fails, log an audit_log row with

     stage='diagnosis_failed', actor='<provider_name>', output_snapshot containing the

     error, and move to the next provider in the chain. If ALL providers in the chain

     fail, fall back to a hardcoded default diagnosis: recommended_action=

     'escalate_to_human', confidence=0, root_cause='diagnosis unavailable — all LLM

     providers failed'.

   - On success: insert a row into diagnoses with all parsed fields, the raw LLM

     response text, and a provider_used column recording which provider actually

     answered. Insert an audit_log row with stage='diagnosis', actor=provider_used.

5. Add a provider_used TEXT column to the diagnoses table (ALTER TABLE or update

   schema.sql).

Write a main() that loops over all risk_events with status='new', diagnoses each,

updates their status to 'diagnosed', and prints progress including which provider

answered each one (e.g. "[groq] risk_id=... diagnosed"). Add a small delay between

calls to respect rate limits. Make this runnable standalone:

python diagnosis/run_diagnosis.py

Also print a final summary: how many diagnoses succeeded on primary provider, how many

needed fallback, how many hit the hardcoded default.
